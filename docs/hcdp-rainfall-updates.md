# HCDP monthly rainfall updates

The source is the official HCDP `GET https://api.hcdp.ikewai.org/raster` endpoint with `datatype=rainfall`, `production=new`, `period=month`, and `extent=statewide`. The [official example notebook](https://github.com/HCDP/hcdp_api_notebook/blob/main/workshop.ipynb) contains an older note saying gridded rainfall ended in 2019. An authenticated, isolated request for September 2026 succeeded on October 20, 2026, confirming that the old cutoff does not apply to this raster. The updater checks completed months newest-first and never fabricates a missing month.

The converter turns an EPSG:4326, north-up GeoTIFF into the website's existing format: `rainfall-values.png` (RGB integer 0 = no data; otherwise `(integer - 1) / 10` mm), `rainfall-overlay.png` (same transparent mask and color ramp), and `rainfall-metadata.json` (period, bounds, unit, status, source, dimensions, valid pixels). It rejects wrong CRS/orientation/bounds, empty or implausible rasters, incompatible PNGs, and mismatched no-data masks. The latest month remains in the original three paths for the NbS map-click lookup.

`scripts/sync_hcdp_rainfall_history.py` checks the latest 24 completed months, archives each available and validated month in `assets/data/rainfall-monthly/YYYY-MM/`, and writes `assets/data/rainfall-months.json`. The Rainfall Map date selector lists only months in that index and loads the selected raster on demand. Missing/unpublished months never appear as choices. The existing September 2026 raster seeds the archive without changing the original files; it was also verified by an authenticated HCDP run on October 26, 2026. An API or validation error stops the run before changing website files. Newest validated data updates the original three paths only after conversion passes. No HCDP token reaches frontend JavaScript.

The API example does not document a reliable final/preliminary indicator in the raster response. Accordingly, new data is marked **preliminary**, never final by assumption. Confirm final status with HCDP before changing the metadata to final.

## Run manually

The repository Actions secret `HCDP_API_TOKEN` supplies authentication; its value stays out of source files and logs. Once this revised workflow is reviewed and available on the default branch, go to **Actions → Update HCDP monthly rainfall → Run workflow**. For an isolated API check, enter a `YYYY-MM` and select **verify_only**. This downloads and validates in an empty temporary directory, uploads only the three generated website files as a one-day artifact, and never changes tracked assets or opens a PR. For the 24-month backfill or a normal update, leave **verify_only** off and `month` empty. The workflow retries every Monday at 18:23 UTC and opens a review pull request only when validated data changes. It does not merge or deploy. A missing month is omitted; an API failure leaves current website files untouched.

For local testing: `python -m pip install -r scripts/requirements-hcdp.txt`, set `HCDP_API_TOKEN` privately in your shell, then run `python scripts/sync_hcdp_rainfall_history.py --months 24 --output-dir /path/to/test-directory`. Do not paste the token into a command, issue, or log. Omit `--output-dir` only when you intend to update the website files locally. A missing token, API failure, or invalid raster leaves the existing assets unchanged. The frontend falls back to the original one-month files if the index is absent; it does not silently substitute an unavailable month when the index is present.
